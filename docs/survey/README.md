# Monorepo survey

This directory holds the static maps, contract traces, and timing measurements gathered by rafa-862 in preparation for
the monorepo cut (epic #801). Every map is read at a named commit, every trace is written by hand from the import graph,
and costs are recorded in the effort store. Read this file first: each entry below names its source and the commit where
the input data was read.

## Files by category

### Static maps and source readings

Generated by running scripts from the repository root; every map's input is read at the commit named. Run
`rafa effort report <task-id>` to see the cost of each reading, recorded under the task that made it.

- **`import-graph.{json,md}`**: Connectivity graph of 1577 source and test files, 32 clusters by in-cluster degree,
  the 30 files of highest betweenness, and cluster membership by folder. Made by `scripts/survey/import-graph.ts`
  reading `src/` and `packages/*/src/` at commit 6c35a2b (docs: add `scripts/survey/import-graph.ts`). JSON: 2-space
  indent, sorted keys, sorted edges and sorted member arrays. Markdown: coverage line, size tables, betweenness top-30.

- **`concepts.{json,md}`**: All defined types, classes and interfaces across the codebase, and their module homes.
  Made by `scripts/survey/concepts.ts` reading TypeScript AST at commit 5a3cbf5 (docs: add `scripts/survey/concepts.ts`).
  JSON: sortedkeys, sorted concept arrays. Markdown: coverage, count by category (type / interface / class), members by
  file, exports from each public module.

- **`provenance.{json,md}`**: The origin commit and date of every file under `src/` and `packages/*/src/`, read from
  git log. Made by `scripts/survey/provenance.ts` at commit e1b25fa (docs: add `scripts/survey/provenance.ts`). JSON:
  sorted files by commit and date. Markdown: coverage, counts by year/month, a histogram of file age.

- **`test-index.{json,md}`**: Module imports, file count and nesting depth for every test file under `src/` and
  `packages/*/src/`, and a baseline for the fourth criterion of epic #801. Made by `scripts/survey/test-index.ts` at
  commit fc9af06 (test: add `scripts/survey/test-index.ts`). JSON: sorted keys and array of test records. Markdown:
  coverage, counts and distribution of index values, the tests at and above the ceiling (128), the top-20 highest-index
  tests, disabled readings and reasons.

All four maps were written to disk at commit 578c594 (docs: run the four map scripts from the repository root) after
their scripts were added. Run the maps again with `scripts/survey/maps.test.ts` (added at 9a015be) to verify they have
not drifted from the current repository.

- **`cluster-map.json`**: The file-to-cluster assignment of the eight-cluster run over non-test files, at base commit
  102d26c: 631 files under `clusters`, each with its cluster (`c1` to `c8`), and under `outside` the 27 files that run
  left in no cluster (isolated or detached). It is not one of the four maps and no script here writes it: it was
  exported once, for rafa-903, from a run kept outside the tracked tree, so `scripts/survey/maps.test.ts` does not
  check it. `import-graph.json` above is a different run, 32 clusters with tests included. JSON: 2-space indent, sorted
  keys, sorted `outside` array.

### Cluster contract traces

One markdown file per cluster, showing the cluster's scope, its boundary with the rest of the graph, and the entry points
that would have to be exported if the cluster became a package. Traces are read by hand against the import graph JSON and
written to document what the monorepo cut must address for each cluster. Every trace file is named `trace-c<NN>-<stem>.md`,
where `<NN>` is the cluster's rank by file count and `<stem>` is the file stem of the member with the highest in-cluster
degree.

- **32 cluster traces** (`trace-c01-github.md` through `trace-c32-cli.md`): Written by hand over 17 commits from commit
  5ee5988 (docs: trace the largest cluster in `docs/survey/import-graph.json` that) through commit 89b9514 (docs: trace
  every cluster in `docs/survey/import-graph.json` still). Each commit adds one or more traces; see `git log
  --oneline -- docs/survey/trace-*.md` for the full list. These are hand-written reads against the import graph JSON,
  not generated by a script, so their content is permanent documentation of what the boundary looks like for each cluster
  as of this point in time.

### Doc inventory and decision sources

- **`doc-inventory.{json,md}`**: Every tracked markdown file under `docs/survey/`, `context/`, and `scripts/`, read for
  headings, backticked paths, context page pointers, and @-imports. Made by `scripts/survey/doc-inventory.ts` at commit
  c134a48 (docs: add `scripts/survey/doc-inventory.ts`). Serves the doc coherence check: every path in backticks must
  resolve, every context pointer must land, and no file outside `CLAUDE.md` may use the `@` import form. JSON: sorted
  docs and sorted sections within each doc. Markdown: coverage line, count of file types, orphaned sections (with no
  path leading to them), and every broken path or pointer.

- **`decision-sources.{json,md}`**: Every line cited in `guidelines.md`, drawn from issue bodies, context pages, and
  code. Made by `scripts/survey/decision-sources.ts` at commit 6f69416 (docs: add `scripts/survey/decision-sources.ts`).
  Used to build the guidelines: 152 code tenets read, 522 decision lines cross-referenced, 231 with a source line
  cited. JSON: sorted sources, sorted decision sections. Markdown: index of rejected lines and context rules, the
  distribution of decisions across categories, decision cross-references that cite both sides of a conflict.

### Guidelines

- **`guidelines.md`**: 78 guidelines extracted by hand from decision-sources.json, marking each as `stated` (a source says
  it in words), `inferred` (the code or pattern stands on it), or `conflicting` (two sources disagree). Written at commit
  bd6c42e (docs: write `docs/survey/guidelines.md` from). Ends with "For #802's alignment Q&A", naming 10 open
  questions that the alignment session needs to resolve. These are the decisions that #802 still holds.

### Test timing

- **`test-timing.md`**: Wall-clock and in-case time for every test file, the 20 slowest files, and files with all cases
  skipped. Made by `scripts/survey/test-timing.ts` at commit caefa06 (test: add `scripts/survey/test-timing.ts`). Shows
  18356 passing tests, 0 failures, 17 skipped, across 925 test files in 366.11 seconds of test time (382.99 wall
  clock). Used to establish the timing baseline for the third criterion of epic #801: test timing is the stable
  reference to measure any test scope growth against when modules move into packages.

## Cost sources

Every script task recorded its work in the effort store. To see the cost and time for each script that made a map or
inventory, run:

``` bash
rafa effort report --format json | jq '.[] | select(.phase == "working") | .name'
```

Then drill into each task with:

``` bash
rafa effort report <task-id> --format json | jq '.[] | .cost'
```

The hand-written traces (cluster contract traces and guidelines) have no separate cost entry because they were written
across multiple scoped task lines; search the plan in #862 for "trace" to see which task lines touched them.

## What #802 still holds

Issue #802, the monorepo survey, opened on 2026-10-06 and shaped this entire plan. It is still the home of:

1. **The alignment prompt and session**: a turn-by-turn conversation where the person reads the traces and guidelines,
   decides the answers to the 10 open questions at the end of `guidelines.md`, and refines the cut strategy before
   work begins. This survey gathers facts; the alignment session decides policy.

2. **The decision records**: each of the 10 open questions (G07, G20, G39, G40, G45, G51, G62, G65, G66, G68, G69, G70,
   G72) carries the sources that pull in different directions. #802 is where those are debated and resolved.

3. **A1, the first alignment answer**: once the answers land in a comment, #802 becomes the record of what rafa will do
   when the cut runs. Epic #801 then depends on that comment, so the cut specs can cite #802 directly.

The six other findings that populated `guidelines.md` (G01–G06, G08–G38, G41–G64, G67, G71, G73–G78) are stated
decisions or stable inference from today's code, needing no further debate. They are the policy that the cut must
follow.

## Verification

Every map and inventory script has a test file under `scripts/survey/` with a `*.test.ts` name. Run the full suite
with:

``` bash
bun test ./scripts/survey/
```

The test runner imports the JSON output of each script and verifies its shape: sorted keys, sorted arrays, required
fields present, and no dropped data. To re-read the codebase and refresh all maps in one command:

``` bash
bun run scripts/survey/maps.test.ts
```

That test exports a `makeAllMaps()` function that the wrap-up calls to ensure the maps are current when this survey
closes.
