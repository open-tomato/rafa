# Monorepo survey

> **Dated record.** This directory is a record of the tree at the survey's own run, commit `6c35a2b`. Each entry below
> names the commit its input was read at. Paths, counts and cluster membership have moved since and are not corrected
> here.

This directory holds the static maps, contract traces, and timing measurements gathered by rafa-862 in preparation for
the monorepo cut (epic #801). Every map is read at a named commit, every trace is written by hand from the import graph,
and costs are recorded in the effort store. Read this file first: each entry below names its source and the commit where
the input data was read.

- **`test-index.baseline.json`**: The baseline the move of #905 is held to for the fourth criterion of epic #801, in the
  unit `packages`. A file's unit is the `name` of the `packages` row of the map `docs/survey/cut-table.json` that lists
  it, or the `unassigned` folder that lists it (`src/ci/`), else the unit of its folder as `cut-table.{json,md}` below
  says. The record names that map by path and sha256 (`d7188c8ed6ff…`, in full under `map`) and the commit it reads,
  `9f07f3d`, in full under `commit`. Written by `bun scripts/survey/test-index.ts --baseline
  --map=docs/survey/cut-table.json` through `scripts/survey/test-index-record.ts`, which reads `src/` and
  `packages/*/src/` at that commit and refuses when a tracked file in scope differs from `HEAD`; it writes nothing and
  exits 1 naming each file the map holds no unit for. Read by `bun scripts/survey/test-index.ts
  --against=docs/survey/test-index.baseline.json --map=docs/survey/cut-table.json`, the guard of
  `scripts/survey/test-index-guard.ts`, which writes nothing and exits 1 when the record's unit is not `packages` or its
  map's sha256 is not the handed map's, when a test that does not meet its kind's rule is not on `unsorted` (a unit or
  contract test reaching a unit beyond its own, a use-case test entering another unit through no public entry), when a
  test the record holds has no imports read now, or when the map holds no unit for a file. The three flags are read by
  `scripts/survey/test-index-args.ts`, which refuses any other argument with the usage text, either mode without
  `--map=<file>`, and `--map=<file>` alone. The record holds 1230 test files (1073 unit, 156 use-case, 1 contract;
  443 spawning a process): 228 meet their kind's rule, 1002 are on `unsorted`, none are unindexed. Read at 9f07f3d
  against itself it prints 0 risen, 1002 unsorted and 228 held, then 0 gone, 0 not read, 0 unindexed and 0 unplaced, and
  exits 0. The record is not one of the four maps, so `scripts/survey/maps.test.ts` does not check it. JSON: 2-space
  indent, keys `unit`, `map`, `commit`, `binReach` (the bin's reach, eleven units), `tests` keyed by path, `unsorted`,
  `unindexed`.

  The index counts the units a test reaches, doubled when it spawns, so the cut moves it three ways. Lightest first:
  1. A test whose index falls because three folders became one package: say it reached three folders of `src/`, which
     now make one package, so it reaches one unit. A fall fails nothing in the guard.
  2. A test whose index rises because one folder split in two: a folder of `src/` is cut across two packages, so a test
     that reached it reaches two units. The guard fails it only when its kind's rule breaks, and then it is risen unless
     it is on `unsorted`.
  3. A spawned test whose reach is the CLI plus one feature: every spawning test is read as running the bin, so its
     reach is the bin's units (`binReach`) plus its feature, and the spawn doubles the total. Its one feature costs
     twice, which makes it the heaviest of the three.

  Keeping the folder baseline and converting it to packages at check time was rejected: the conversion is exactly the
  change of unit the guard must not hide.

### Cluster contract traces

One markdown file per cluster, showing the cluster's scope, its boundary with the rest of the graph, and the entry points
that would have to be exported if the cluster became a package. Traces are read by hand against the import graph JSON and
written to document what the monorepo cut must address for each cluster. Every trace file is named `trace-c<NN>-<stem>.md`,
where `<NN>` is the cluster's rank by file count and `<stem>` is the file stem of the member with the highest in-cluster
degree.

- **32 cluster traces** (`trace-c01-github.md` through `trace-c32-cli.md`): Written by hand over 17 commits from commit
  5ee5988 (docs: trace the largest cluster in `docs/survey/import-graph.json` that) through commit 89b9514 (docs: trace
  every cluster in `docs/survey/import-graph.json` still). Each commit adds one or more traces; see `git log
  --oneline -- docs/survey/trace-*.md` for the full list. These are hand-written reads against the import graph JSON,
  not generated by a script, so their content is permanent documentation of what the boundary looks like for each cluster
  as of this point in time. They follow the 32 clusters of the survey's own run: the `import-graph.json` written
  again since holds 44 clusters of 2165 files under other names and on the moved paths, and no trace was rewritten for it.

## Cost sources

Every script task recorded its work in the effort store. To see the cost and time for each script that made a map or
inventory, run:

``` bash
rafa effort report --format json | jq '.[] | select(.phase == "working") | .name'
```

Then drill into each task with:

``` bash
rafa effort report <task-id> --format json | jq '.[] | .cost'
```

The hand-written traces (cluster contract traces and guidelines) have no separate cost entry because they were written
across multiple scoped task lines; search the plan in #862 for "trace" to see which task lines touched them.

## What #802 still holds

Issue #802, the monorepo survey, opened on 2026-10-06 and shaped this entire plan. It is still the home of:

1. **The alignment prompt and session**: a turn-by-turn conversation where the person reads the traces and guidelines,
   decides the answers to the 10 open questions at the end of `guidelines.md`, and refines the cut strategy before
   work begins. This survey gathers facts; the alignment session decides policy.

2. **The decision records**: each of the 10 open questions (G07, G20, G39, G40, G45, G51, G62, G65, G66, G68, G69, G70,
   G72) carries the sources that pull in different directions. #802 is where those are debated and resolved.

3. **A1, the first alignment answer**: once the answers land in a comment, #802 becomes the record of what rafa will do
   when the cut runs. Epic #801 then depends on that comment, so the cut specs can cite #802 directly.

The six other findings that populated `guidelines.md` (G01–G06, G08–G38, G41–G64, G67, G71, G73–G78) are stated
decisions or stable inference from today's code, needing no further debate. They are the policy that the cut must
follow.

## Verification

Every map and inventory script has a test file under `scripts/survey/` with a `*.test.ts` name. Run the full suite
with:

``` bash
bun test ./scripts/survey/
```

The test runner imports the JSON output of each script and verifies its shape: sorted keys, sorted arrays, required
fields present, and no dropped data. To re-read the codebase and refresh all maps in one command:

``` bash
bun run scripts/survey/maps.test.ts
```

That test exports a `makeAllMaps()` function that the wrap-up calls to ensure the maps are current when this survey
closes.
