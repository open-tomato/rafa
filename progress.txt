- `Bun.YAML.parse` facts, measured on bun 1.3.14, for any YAML reader here
  (the `rafa:report` parser included). An empty, whitespace-only,
  comment-only or bare `---` input gives `null`. A multi-document stream
  gives an ARRAY of documents. Duplicate keys: the last one wins silently.
  Malformed input throws a `SyntaxError` whose message has no line or
  column. A TAB-indented child does NOT throw: it parses as a sibling
  top-level key. Keys spelled `constructor`, `toString` or `__proto__` come
  back as ordinary own keys, so look keys up with `Map`/`Set`, never `in`
  or an object index. Integer-like keys enumerate first, so
  `Object.entries` order is not source order.
- Config lives in `src/config.ts`. `loadConfig(root, cli, warn?)` reads
  `.rafa/config.yaml` and ranks command line > file > `CONFIG_DEFAULTS`.
  `parseConfigText` and `resolveConfig` are pure, and refusals throw
  `ConfigError` (with `.problems`). Unknown keys come back as `extras` plus
  `warnings`, never as a refusal. Pass command-line values RAW, keyed by
  setting (`{ store, inject }`, as `argValue` returns them): the resolver
  validates them, so callers should not pre-validate. The file key
  `plan.inject` is the field `inject`.

- The effort store port is `src/effort/store/types.ts`. It holds the
  kind-parameterised `EffortStore` (`append`, `keys` and `read`, each
  taking an `EffortRowKind`) and the closed row map `EffortRowByKind`.
  It also declares `SessionEffortRow`, which `effort/collect.ts` now
  re-exports. Finally it holds `EFFORT_KEY_PROJECTIONS`: `sessions` are
  keyed by `sessionId` and `commits` by `sha`, and a keyless row
  answers null. The port's `AppendResult` is `{ path, appended,
  skipped }` only. NDJSON-only readings (`separatedPartialLine`, the
  line arithmetic) belong on a backend's own wider type.
- Declare a port interface with PROPERTY signatures
  (`keys: (kind: K) => ...`), not method signatures. Measured with this
  repo's tsc: a backend whose parameter is narrower than the port's is
  refused under a property signature (TS2322). Under a method
  signature it is silently accepted, because method parameters are
  checked bivariantly. For a closed per-kind map use a `type` alias. An
  interface can be widened from another file by declaration merging,
  while re-declaring an alias fails with TS2300.

- The SQLite backend is `src/effort/store/sqlite.ts`.
  `openSqliteStore(repoRoot)` gives the port plus `path(kind)`, which
  answers the one file every kind shares, `.ralph/effort/effort.sqlite`.
  There is one table per kind (`sessions` keyed by `session_id`,
  `commits` keyed by `sha`), each holding `seq`, the key and `row_json`.
  `row_json` is the exact line text the NDJSON backend writes, so the
  two backends' rows are byte-identical by construction. The schema
  history is `SQLITE_MIGRATIONS`. A schema change APPENDS an entry and
  never edits a shipped one. The version is the array's length, held in
  `PRAGMA user_version`. `migrateSchema(db, path, migrations?)` is
  exported so a synthetic history can be driven on a `:memory:` db.
- `bun:sqlite` facts, measured on bun 1.3.14 on macOS, where bun uses
  Apple's system SQLite (3.51.0 here):
  - It is synchronous: `.all()` returns an array and `Statement.run`
    returns `{ changes, lastInsertRowid }`, neither a Promise, so a
    backend implements the synchronous store port without awaiting.
  - `new Database(path)` with no options CREATES a missing file.
    `{ readwrite: true }`, with or without `create: false`, refuses one
    with `SQLITE_CANTOPEN` and creates nothing.
  - A directory throws `SQLITE_CANTOPEN` at open. A non-SQLite file
    opens fine and throws `SQLITE_NOTADB` at the first statement. A
    zero-byte file is an empty database at `user_version` 0.
  - `INSERT OR IGNORE` also swallows NOT NULL and CHECK violations, as a
    silent 0-change insert. `ON CONFLICT (col) DO NOTHING` absorbs only
    that conflict and throws on anything else.
  - A fresh database uses journal mode `delete` and leaves no sidecar
    file after close. Under WAL on macOS, the `-wal` and `-shm` files
    OUTLIVE the close, so byte-comparing the main file only means
    something without WAL.
  - A transaction whose inserts all hit `DO NOTHING` leaves the file
    byte-identical. `PRAGMA user_version = N` and DDL roll back with
    their transaction.
  - Binding a string holding a lone UTF-16 surrogate is LOSSY, and can
    collide: `ab\uD800cd` is stored as `ab\u{10063}d`, the same text a
    real astral character gives. A trailing lone high surrogate was
    stored as `''`. The same string inside `JSON.stringify` text
    round-trips.
  - There is no busy timeout by default. A second writer that runs
    `BEGIN IMMEDIATE` while another connection holds one gets
    `SQLITE_BUSY` at once.
  - A default `db.close()` after `db.transaction(...)` releases the
    file descriptor. `lsof` showed 1 while open and 0 after.
- The Write and Edit tools decoded a plain four-hex-digit unicode
  escape of a Latin-1 letter into the literal letter, in file content
  and in `new_string` alike, so two Edits "made no change". Surrogate
  escapes such as `\uD800`, and braced ones such as `\u{1F345}`,
  arrived as typed. After writing an escape into source, list the
  file's non-ASCII code points with a bun one-liner to see what really
  landed. The braced form (`\u{e9}`) got through where the plain form
  kept being decoded.

- `import/order` puts every `import type` line in ONE group, and
  eslint-plugin-import 2.32's sorter never compares a sibling path with
  a parent one by name: it stops at the differing first segment and
  sorts by segment COUNT, fewer `/` first. So `./types.js` must precede
  `../../config.js` in the type block, while `../store.js` and
  `./types.js` tie and pass in either order (`store/ndjson.ts`). Value
  imports sit in separate parent and sibling groups, so it never arises
  there. An import of `./index.js` is the `index` group: after the
  sibling group, behind its own blank line. `./store/index.js` from the
  directory above it is NOT: it is an ordinary sibling import, and lint
  passes it at the end of the sibling block with no blank line
  (`effort/collect.ts`).
- The collector, `src/effort/collect.ts`, goes through the store port.
  `collectEffort` takes `store` (an `EffortStore`). Without one it
  resolves the store ONCE per run, `loadConfig(repoRoot, {}, log)` then
  `selectEffortStore`, before either half reads a log or runs git. So
  to target a backend (the parity tests), pass `openNdjsonStore(root)`
  or `openSqliteStore(root)`. A run given no store, under a root with no
