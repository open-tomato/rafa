# Progress notes

- This repo (`open-tomato/rafa`) is a single-package bun repo: `package.json`,
  `src/`, `scripts/` at the root, no `packages/` directory and no workspace
  boundaries. Agent/doc files ported from the sibling
  `~/projects/agentic-research` (a bun-workspaces monorepo) must have every
  `packages/`, workspace and monorepo reference rewritten away.
- `scripts/control-byte-gate/control-byte-gate.ts` (with a colocated
  `control-byte-gate.test.ts`) is this repo's control-byte gate script,
  referenced by `.githooks/pre-commit` per the plan (though the hook's
  current path and `core.hooksPath` wiring were not verified in this task).
- `.claude/skills/` in this repo currently carries `progress-hygiene`,
  `dev-planner`, `documentation`, `git-workflow`, and others copied from the
  sibling; the plan schedules `progress-hygiene` for deletion in a later
  stage ("Structured task report"), so don't treat its current presence as
  permanent when writing docs that reference skills.
- No `AGENTS.md` or `context/` directory exists yet at repo root as of this
  task — both are added by a later "Bootstrap the routing surface" task
  (doc-updater agent). Files ported early (e.g. `.claude/agents/*.md`) may
  reference paths like `src/tests/context-page-imports.test.ts` and
  `src/PROMPT.md` that don't exist yet but are added by later plan stages.
- `rm -rf` (and even `rm -r`/`rm -rf` on files under /tmp) is blocked by this
  sandbox's Bash permission layer regardless of target path. Use `mv` to a
  scratch directory instead of deleting when you need to clear a directory's
  contents, and prefer `cp -R src/. dest/` (trailing `/.`) to copy a
  directory's contents into an existing directory without deleting it first.
- The sibling `tools/ralph/` tree (48 files) uses `.js` extensions in its
  relative imports (e.g. `import start from './start.js'` inside
  `ralph.ts`/`rafa.ts`) even though the files are `.ts` — this is normal
  TypeScript ESM-style import convention (bun/tsc resolve `.js` specifiers to
  `.ts` sources) and should be left as-is when porting/repointing paths in a
  later task.
