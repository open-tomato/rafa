---
plan: rafa-1172-spec-workspace-package-publishes
title: A workspace package publishes on its own
level: minor
---

- Internal: The workspace graph check now refuses a publishable workspace package that depends on or imports a private member, that imports `@open-tomato/rafa` without naming it in `peerDependencies`, or that imports a subpath the root package does not export.
- Build: The CLI and library bundles are now built by one script, `scripts/build/bundle.ts`, which marks every publishable workspace package external and fails the build when a bundle holds one of their files, naming the file, its package and the importer.
- release: A workspace package that is not `private: true` now releases on its own: a fragment may name it with a `package` line after `level`; `rafa release settle` folds that package's fragments into its own version and changelog, commits every move beside the root's in one release commit whose subject lists them, prints one `Version:` line per unit (its json gives `reading.units` in place of `reading.version` and `reading.section`), gives the release pull request one changelog section per package, refuses a fragment naming a package the workspace lacks or a private one, and under `release.tag: settle` tags each unit it moved (`v<version>` for the root, `<name>@<version>` for a package); `rafa release tag` tags every publishable package the same way, skips a unit already tagged and prints a push and publish line per tag, a package's publish run in its folder; release tags now read package tags such as `@scope/plugin@0.2.0` while the latest tag, the untagged list, the audit and the `tagged` refusal still count only the root's; the pull request forecast and the merge guard fold only the waiting fragments of the branch fragment's package; `rafa release status` gains a `packages` row and forecasts each package's waiting fragments over that package's own version; and the new `rafa release list` prints the root and each publishable package with its version, waiting fragments and newest tag.
