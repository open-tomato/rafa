title: The release ladder, level 2 first: CI publishes a pushed tag with provenance
level: minor
---

- release: The release ladder lets a project choose how much of its release runs on its own. The new `release.publish` setting (`manual` by default, or `ci`) says who publishes a tagged version, and `rafa init` writes it as a commented line under `release`. `rafa release publish` runs `release.publishCommand` for each release tag at HEAD and skips the versions the registry already holds, so a rerun after a partial publish publishes only what is missing. `rafa release workflows [--write]` lists the ladder's workflow files, whether the configured level needs each and whether it is present, missing or differs from the template, and writes the missing ones. Four workflow templates ship: `release-publish.yml` runs the gates on a pushed tag and publishes with npm trusted publishing, `release-tag.yml` tags and publishes when the release pull request merges, `release-settle.yml` settles, tags and publishes on every push to the default branch, and `release-bot-fragment.yml` writes, commits and pushes the release fragment of a Dependabot pull request, at `patch` for a production dependency and `none` otherwise. `rafa release fragment` writes one change fragment for a branch with no wrap-up, named free of the fragments waiting on the base. Under `release.publish: ci`, `rafa release tag` says the pushed tag publishes through `release-publish.yml` instead of printing a publish line, and the release pull request says CI tags and publishes on the merge under `release.tag: settle`.
- doctor: `rafa doctor` prints a Release ladder row under the release row naming the level the release keys put the project at, and warns with each missing workflow, `id-token` permission or manifest field together with what supplies it; the exit code never changes.
- build: The build copies a template directory that holds only YAML files, so the release workflow templates reach `dist/`.
- docs: The CI settle guide shows the shipped `release-settle.yml` template instead of an example naming a flag that does not exist, and points at `rafa release workflows --write` as the way to install it.
